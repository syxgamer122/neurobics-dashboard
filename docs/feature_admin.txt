TỔNG HỢP TÍNH NĂNG: QUẢN TRỊ ADMIN (ADMIN CONTROL-PLANE)
DỰ ÁN: MINDGEM
===============================================================================

1. TỔNG QUAN (OVERVIEW)
-------------------------------------------------------------------------------
Tính năng Quản trị Admin (Admin Panel / DB Control Plane) là hệ thống trung tâm 
dành riêng cho quản trị viên (người dùng có quyền role === "admin") trong dự án 
MindGem. System này cho phép Super Admin theo dõi toàn bộ hệ thống 
theo thời gian thực, quản lý hồ sơ người chơi, thao tác điều chỉnh điểm số các 
trục nhận thức, xử lý dữ liệu và quản trị tài khoản người dùng.

Các khả năng chính của tính năng Admin:
- Giao diện Control Plane chuyên biệt: Cyberpunk / Database Dashboard với hiệu ứng 
  neon, hiển thị trạng thái kết nối Supabase, độ trễ cơ sở dữ liệu (DB Latency) 
  và tổng số lượng người dùng (profiles).
- Quản lý người dùng & Bảng dữ liệu Live Data Grid: Hiển thị danh sách toàn bộ 
  người chơi (`public.profiles`) với các thông số điểm trục (Logic, Memory, Speed, 
  Focus, Spatial), XP và số lượt chơi (Sessions).
- Điều chỉnh điểm chỉ số & XP (Admin Grant): Cho phép cộng thêm (`add`) hoặc 
  gán đè (`set`) điểm số cho 5 trục nhận thức và điểm kinh nghiệm (Total XP) của 
  bất kỳ người dùng nào, hỗ trợ nút bấm nhanh preset (10, 50, 100, 500, 1000).
- Reset điểm số (Reset Scores): Đưa toàn bộ điểm chỉ số 5 trục, XP và số liệu 
  phiên chơi của người dùng được chọn về 0.
- Xóa tài khoản vĩnh viễn (Danger Zone / Delete User): Xóa hoàn toàn người dùng 
  bao gồm Avatar lưu trữ ở Supabase Storage, Auth Account trong Supabase Auth 
  và thông tin Profile trong cơ sở dữ liệu Postgres.
- MFA Required (Bảo mật 2FA): Yêu cầu quản trị viên phải xác thực 2 bước (MFA). Mọi hành động chỉnh sửa/xóa đều phải qua hàm `requireAdmin` kiểm tra `aal === "aal2"` trong JWT.
- Nhật ký hoạt động (Activity Log): Theo dõi log thao tác console client-side của phiên bản Admin hiện hành.


2. KIẾN TRÚC HỆ THỐNG (ARCHITECTURE)
-------------------------------------------------------------------------------
Mô hình triển khai tách biệt giữa Client (React / Next.js UI) và Server (Supabase 
Edge Functions running Deno + Hono Framework), giao tiếp qua HTTPS RESTful API.

[ Client UI Layer ] 
  └─ AdminPanel (Container / Controller)
       ├─ AdminShell (Theme Shell & Layout Grid)
       ├─ AdminOverview (System Telemetry & Metrics)
       ├─ AdminControls (Grant / Reset / Delete Forms)
       ├─ ProfilesGrid (Live User Table)
       ├─ ActivityLog (Console Log Monitor)
       └─ AccessDenied (Security Fallback Guard)

[ Client API Layer ]
  └─ src/app/lib/api/admin.ts (SDK wrappers using serverPost)

[ Server Edge Layer ]
  └─ supabase/functions/server/routes/admin.ts (Hono API endpoints)
       ├─ POST /server/admin-grant  (Apply points/XP)
       ├─ POST /server/admin-reset  (Zero out scores)
       └─ POST /server/admin-delete-user (Purge Auth + Storage + Profile)

[ Database & Auth Layer ]
  ├─ Supabase Auth (admin.deleteUser)
  ├─ Supabase Storage (bucket: "avatars")
  ├─ Postgres Table: public.profiles
  └─ Postgres RPC: sync_achievements_for(p_user)

4. CHI TIẾT TRIỂN KHAI (IMPLEMENTATION DETAILS)
-------------------------------------------------------------------------------
A. KIỂU DỮ LIỆU VÀ MAPPING CỘT (TYPES & COLUMN MAPPING):

- Kiểu chế độ grant (GrantMode):
  `type GrantMode = "add" | "set";`

- Kiểu giá trị form grant (GrantAxes):
  `type GrantAxes = Record<AxisKey, string>;`
  với `AxisKey = "logic" | "memory" | "speed" | "focus" | "spatial"`

- Payload gửi tới server (AdminGrant):
  ```typescript
  type AdminGrant = {
    axes?: Partial<Record<AxisKey, number>>;
    xp?: number;
    mode?: "add" | "set";
  };
  ```

- Mapping từ AxisKey sang Cột Database (AXIS_COLUMNS):
  - logic   -> `algebraic_logic_score`
  - memory  -> `memory_score`
  - speed   -> `speed_score`
  - focus   -> `focus_score`
  - spatial -> `spatial_score`

B. HẰNG SỐ VÀ CÁC NGƯỠNG AN TOÀN (CONSTANTS & BOUNDS):

- Bảng màu Admin Control-Plane (ADMIN_COLORS):
  - green:  "#00FF9C" (Màu chủ đạo neon)
  - blue:   "#00D4FF" (Màu chỉ số / latency)
  - amber:  "#F59E0B" (Màu cảnh báo / XP)
  - red:    "#F43F5E" (Màu nguy hiểm / xóa)
  - purple: "#A855F7" (Màu target user / selected)

- Ngưỡng giới hạn điểm số trục (Axis Bounds):
  `[0, 1000]` điểm. Mọi phép cộng/gán đều được kẹp (clamp) bằng công thức:
  `nextScore = Math.max(0, Math.min(1000, Math.round(calculatedScore)))`

- Ngưỡng giới hạn XP (XP_MAX Bound):
  `XP_MAX = 200,000,000` (200 triệu XP, tương ứng level ~2000).
  Edge Function chỉ làm tròn delta bằng `Math.round(calculatedDelta)`. Ràng buộc biên nằm ở RPC admin_grant_tx — chặn abs(delta) > 10,000,000 và chặn tổng sau khi cộng vượt XP_MAX = 200,000,000.
  *Lý do thiết kế*: Tránh trường hợp Admin gõ nhầm nhiều chữ số 0 làm `total_xp` 
  vượt quá giới hạn, đẩy level lên hàng triệu và làm hỏng Bảng xếp hạng.

C. THUẬT TOÁN & LOGIC XỬ LÝ CHÍNH:

1. Logic tính toán Grant (Thêm / Gán điểm):
   - Nếu `mode === "set"`: Giá trị mới = `amount`
   - Nếu `mode === "add"`: Giá trị mới = `current_score + amount`
   - Kẹp vào khoảng `[0, 1000]` cho 5 trục. Với XP, truyền thẳng `delta` xuống RPC `admin_grant_tx`. RPC sẽ chặn cứng lỗi với `abs(delta) > 10,000,000` hoặc nếu tổng vượt `200,000,000`.

2. Tự động đồng bộ Huy hiệu / Thành tựu (Badge Auto-Sync):
   Khi XP được cập nhật thành công qua Admin Grant, server chủ động gọi RPC:
   `await adminClient.rpc("sync_achievements_for", { p_user: targetId });`
   Giúp huy hiệu của người dùng được cập nhật ngay lập tức mà không phải chờ 
   người dùng tự mở bảng thành tựu.

3. Logic Reset Scores:
   Gọi RPC `admin_reset_stats`:
   ```sql
   admin_reset_stats(p_target uuid, p_actor uuid)
   -- stats_epoch = now()
   -- 5 trục = 0, session counters = 0
   -- last_active_date = now()   -- tránh decay tối đa ngay sau reset, fix lỗi daysSince(null)
   -- KHÔNG xóa xp_events (ngoại trừ game = \'achievement\' để tránh double XP) (giữ audit trail)
   ```



4. Logic Xóa tài khoản Triệt để (3-Tier Account Purge):
   - Bước 1: Liệt kê và xóa toàn bộ file ảnh đại diện trong Supabase Storage bucket 
     `avatars` tại thư mục `${targetId}/*`.
   - Bước 2: Gọi Supabase Auth Admin API để xóa người dùng khỏi hệ thống xác thực:
     `await adminClient.auth.admin.deleteUser(targetId);`
     Nếu DB có thiết lập FK `ON DELETE CASCADE`, profile sẽ tự động bị xóa.
   - Bước 3: Đảm bảo tính an toàn (fallback), gọi lệnh xóa trực tiếp trong DB:
     `await adminClient.from("profiles").delete().eq("id", targetId);`
   - Chống tự xóa: Server kiểm tra `if (targetId === user.id)` và từ chối xóa với 
     mã lỗi HTTP 400 (`Use delete-account for your own account`).

5. Console Log Buffer & DB Latency Telemetry:
   - Client duy trì mảng `log` chứa tối đa 60 dòng gần nhất, định dạng 
     `[HH:mm:ss] Action details`.
   - Đo thời gian query DB thực tế bằng `performance.now()` khi fetch leaderboard.
   - `AdminOverview` có hiệu ứng sóng nhịp tim (pulse wave) cập nhật qua 
     `setInterval` 1400ms dùng hàm lượng giác: `Math.sin((index + beat) * 0.9)`.

6. BẢO MẬT & VALIDATION (SECURITY & VALIDATION)
-------------------------------------------------------------------------------
1. Phân quyền Phòng thủ Đa tầng (Multi-Layer Defense in Depth):
   - Tầng UI Client: Kiểm tra `profile.role === "admin"`. Nếu không phải admin, 
     hệ thống chặn không render panel mà hiển thị giao diện `<AccessDenied />`.
   - Tầng Client SDK: Mọi hàm tác vụ trong `admin-panel.tsx` đều có guard clause 
     `if (!isAdmin || busy) return;`.
   - Tầng Server Authentication: Endpoint gọi `authenticatedUser(c)` để xác thực 
     JWT bearer token từ header request.
   - Tầng Server Authorization: Endpoint gọi `requireAdmin(c)` để truy vấn 
     bảng `profiles` kiểm tra cột `role === 'admin'` và đồng thời kiểm tra token 
     JWT xem `aal === 'aal2'` (MFA). Nếu vi phạm, lập tức từ chối bằng mã lỗi 
     HTTP 403 Forbidden.

2. Sử dụng Service Role (Admin Client):
   Server Edge Function dùng `adminClient` (khởi tạo với `SUPABASE_SERVICE_ROLE_KEY`) 
   để có quyền tối cao bypass RLS khi thực hiện các tác vụ quản trị hệ thống và 
   thao tác với Supabase Auth Admin SDK.

3. Kẹp biên Dữ liệu & Chống ô nhiễm (Input Sanitation & Bounds Enforcement):
   - Hàm `parseGrantField()` loại bỏ khoảng trắng, kiểm tra `Number.isFinite()`, 
     chỉ chấp nhận giá trị số hợp lệ.
   - Kẹp biên 5 trục chỉ số trong khoảng `[0, 1000]`.
   - RPC sẽ lo phần giới hạn an toàn của XP delta và tổng XP. Mọi giá trị delta vô lý đều bị từ chối ở tầng database.

4. Chống Tự Xóa Tài khoản Không An Toàn:
   Server kiểm tra `if (targetId === user.id)` trong route `admin-delete-user` 
   để ngăn Admin dùng nhầm route xóa người dùng khác nhằm tự xóa chính mình, bắt 
   buộc phải dùng quy trình `delete-account` cá nhân chuẩn để dọn dẹp session.

5. Audit Logging (Ghi vết kiểm toán):
   Các thao tác can thiệp dữ liệu như `admin.grant` và `admin.reset` được ghi log 
   server bất biến thông qua bảng `admin_audit` (ADR-0006) với thông tin chi tiết: 
   actor (ID của Admin thực hiện), target_id, action, details (axes, xp) và 
   timestamp. Bảng này lưu trữ 365 ngày để phục vụ điều tra.
