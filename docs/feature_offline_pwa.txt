1. TỔNG QUAN (OVERVIEW)
-------------------------------------------------------------------------------
Tính năng Offline & Progressive Web App (PWA) trong hệ thống MindGem cung cấp trải nghiệm liền mạch cho người dùng ngay cả khi không có kết nối Internet hoặc khi kết nối mạng chập chờn. 

Mục tiêu chính của hệ thống bao gồm:
- PWA Support: Khả năng cài đặt ứng dụng trực tiếp lên thiết bị (Desktop, Android, iOS) với giao diện độc lập (display: standalone), hỗ trợ biểu tượng tùy chỉnh (maskable icons), phối màu giao diện mượt mà (#050914) và bộ lắng nghe sự kiện cài đặt chuẩn hóa.
- Offline Playing (Chế độ chơi ngoại tuyến): Cho phép người dùng tiếp tục chơi các trò chơi rèn luyện trí nhận thức khi không có mạng. Các ván đấu được tạm lưu ở bộ nhớ local và tự động tính điểm / XP tạm thời để hiển thị kết quả ngay tức thì.
- Guest Mode (Chế độ chơi thử dành cho Khách): Người dùng mới có thể trải nghiệm toàn bộ các game mà không cần đăng ký tài khoản. Điểm số và tiến trình được đồng bộ lên máy chủ y hệt người dùng đã đăng ký (ADR-0007).
- Offline Queue & Auto Sync: Lưu giữ các ván chơi chưa đồng bộ trong LocalStorage (`neurobics.offline_queue.[userId]`) theo cơ chế FIFO (tối đa 200 ván). Khi thiết bị có mạng trở lại, hệ thống sẽ tự động kích hoạt tiến trình đồng bộ theo từng batch (tối đa 25 ván/batch) lên Supabase Edge Functions server.


2. KIẾN TRÚC HỆ THỐNG (ARCHITECTURE)
-------------------------------------------------------------------------------
Hệ thống được thiết kế theo kiến trúc phân tầng (Client-Server Split) độc lập nhưng phối hợp chặt chẽ qua cơ chế Ticket và Event-Driven.

[CLIENT LAYER]
  ├── PWA Manager (use-pwa-install.ts)
  │     └── Lắng nghe beforeinstallprompt, appinstalled, display-mode: standalone
  ├── Round Submission Orchestrator (use-round-submission.ts)
  │     ├── Check Profile -> estimateRoundResult()
  │     ├── Online Auth User -> startRound() + submitRound() (api.ts)
  │     └── Offline Fallback -> pushOfflineRound() (offline-queue.ts) + estimateRoundResult()
  ├── Offline Storage & Queue (offline-queue.ts)
  │     ├── LocalStorage key: "neurobics.offline_queue.[userId]" (FIFO max 200)
  │     └── Event: "offline-queue-updated"
  └── Auto Sync Engine (use-offline-sync.ts)
        ├── Lắng nghe "online" & "offline-queue-updated"
        └── Gọi syncOfflineQueue(syncOfflineRounds) -> Batch API

[SERVER LAYER - Supabase Edge Function / Hono]
  ├── Ticket Manager (POST /server/start-round)
  │     ├── Mint 1-time round_ticket
  │     └── Rate limit: 20 ticket starts / phút / user
  ├── Direct Submission (POST /server/submit-round)
  │     ├── Validate ticket & serverElapsedMs
  │     ├── Anti-cheat Inspection (hard reject / soft flag)
  │     └── RPC: submit_round_transaction
  └── Offline Batch Sync (POST /server/sync-offline-rounds)
        ├── Validate batch size (<= 25 rounds)
        ├── Validate offline round age (<= 7 ngày)
        ├── Check idempotency qua client_round_id
        ├── Mint real ticket in DB per round
        ├── Anti-cheat Inspection (+ Soft Flag "Offline sync timing bypass")
        └── RPC: submit_round_transaction per valid round

B. CÁC HẰNG SỐ QUAN TRỌNG
- `OFFLINE_QUEUE_KEY`: `"neurobics.offline_queue.[userId]"` - Key lưu trữ hàng đợi trong LocalStorage.
- `MAX_QUEUE`: `200` - Số lượng ván đấu tối đa lưu giữ trong hàng đợi local (FIFO).
- `MAX_SYNC_BATCH`: `25` - Số ván tối đa gửi lên server trong 1 HTTP request đồng bộ.
- `MAX_OFFLINE_AGE_MS`: `7 * 24 * 3600_000` (7 ngày) - Tuổi thọ tối đa của ván offline được server chấp nhận.
- `MAX_TICKET_STARTS_PER_MINUTE`: `20` - Hạn ngạch tạo ticket khởi tạo ván / phút / user trên server.

C. THUẬT TOÁN & LOGIC XỬ LÝ CHI TIẾT

1. Hàng đợi Offline & Quản lý Bộ nhớ (`offline-queue.ts`):
   - Khi ghi ván mới (`pushOfflineRound`):
     ```typescript
     const queue = getOfflineQueue();
     if (queue.length >= MAX_QUEUE) {
       queue.shift(); // Thuật toán FIFO: loại bỏ ván cũ nhất khi đạt ngưỡng 200
     }
     queue.push({
       ...round,
       clientRoundId: crypto.randomUUID(),
       schemaVersion: 1,
       createdAt: new Date().toISOString(),
     });
     writeOfflineQueue(queue); // Ghi vào localStorage & dispatch event "offline-queue-updated"
     ```
   - Chống Race Condition khi đồng bộ (`syncOfflineQueue`):
     Để tránh mất các ván người dùng vừa hoàn thành trong lúc request API `syncEndpoint` đang chờ (await), hàm sẽ đọc lại hàng đợi tươi (`freshQueue = getOfflineQueue()`) trước khi tiến hành lọc bỏ các ván đã chốt (`settledIds` chứa trạng thái `ok`, `duplicate`, `rejected`):
     ```typescript
     const freshQueue = getOfflineQueue();
     const newQueue = freshQueue.filter((item) => !settledIds.has(item.clientRoundId));
     writeOfflineQueue(newQueue);
     ```

2. Tự động Đồng bộ Ngoại tuyến (`use-offline-sync.ts`):
   - Hook lắng nghe 2 sự kiện: `window.addEventListener("online", handleOnline)` và `window.addEventListener("offline-queue-updated", onQueueUpdated)`.
   - Sử dụng `syncingRef = useRef(false)` làm cờ khóa (Mutex) chống việc kích hoạt nhiều tiến trình đồng bộ song song khi có nhiều sự kiện phát ra liên tiếp.
   - Khi đồng bộ thành công, kích hoạt sự kiện toàn cục `window.dispatchEvent(new Event("offline-sync-complete"))`.

3. Cài đặt PWA & Kiểm tra Môi trường (`use-pwa-install.ts`):
   - Sử dụng pattern React 18 `useSyncExternalStore` để đăng ký lắng nghe sự kiện mà không bị tearing trong chế độ Concurrent Rendering.
   - Nhận diện môi trường iOS:
     ```typescript
     function detectIos(): boolean {
       if (typeof navigator === "undefined") return false;
       return (
         /iPad|iPhone|iPod/i.test(navigator.userAgent) ||
         (navigator.platform === "MacIntel" && navigator.maxTouchPoints > 1)
       );
     }
     ```
   - Nhận diện chế độ Standalone (Đã cài đặt):
     ```typescript
     function detectStandalone(): boolean {
       if (typeof window === "undefined") return false;
       const iosStandalone = (navigator as Navigator & { standalone?: boolean }).standalone;
       return Boolean(iosStandalone || window.matchMedia("(display-mode: standalone)").matches);
     }
     ```

4. Luồng Chơi & Dự phòng Ngoại tuyến (`use-round-submission.ts`):
   - Khi chọn Game: Gọi `prepareRound(game)`. 
     
     + Gọi API `startRound(game)` để lấy ticket thật từ server.
     + Nếu Mất mạng (`isNetworkErrorLike(err)`): Tự động cấp ticket dự phòng `offline-{game}-{now}`.
   - Khi Hoàn thành Ván (`completeRound`):
     
     + Nếu ticket là `"offline-"` hoặc lệnh `submitRound` ném lỗi mạng (`isNetworkErrorLike`):
       Gọi `pushOfflineRound(...)` để đẩy vào queue local, đồng thời tính điểm tạm thời bằng `estimateRoundResult` để cập nhật UI ngay cho người chơi.

5. Chấm điểm Cục bộ (`estimateRoundResult`):
   - Khách (Guest) được xử lý y hệt người dùng thật thông qua cơ chế Server Auth. Tất cả ván chơi đều được gửi lên máy chủ hoặc offline queue.
   - Sử dụng một module riêng trên client (UI-only) để tính điểm tạm thời (provisional). Kết quả này được hiển thị dưới dạng "Pending Sync" và không làm thay đổi bảng xếp hạng hay Brain Age cho đến khi được server xác nhận. Tuyệt đối không import các logic chống gian lận hay `scoreAndValidate` từ server (để tránh rò rỉ ngưỡng anti-cheat).

6. Xử lý Đồng bộ ở Server (`supabase/functions/server/routes/rounds.ts`):
   - Endpoint `POST /server/sync-offline-rounds` nhận mảng `rounds` (tối đa 25 ván).
   - Kiểm tra thời gian khởi tạo ván `startedAt`: Từ chối nếu `startedAt` lớn hơn thời gian hiện tại > 60s hoặc cũ hơn 7 ngày (`MAX_OFFLINE_AGE_MS`).
   - Kiểm tra Idempotency: Tra cứu DB `round_tickets` xem đã có ticket nào chứa `client_round_id` này và đã `submitted_at` chưa. Nếu rồi -> Trả về status `"duplicate"`.
   - Tạo Ticket Thật: Nếu chưa có ticket, insert một bản ghi ticket thật vào DB `round_tickets` với `client_round_id`.
   - Kiểm tra Anti-cheat (`inspectRound`): Bổ sung Soft Flag đặc thù: `"Offline sync: timing verification bypassed"`. Nếu phát hiện Hard Flag gian lận -> Đốt ticket (`submitted_at = now`) và trả về status `"rejected"` với code `"anticheat_hard"`.
   - Ghi nhận giao dịch DB (`submit_round_transaction`): Cập nhật Rating trục, XP, và lịch sử ván chơi nguyên tử (Atomic Transaction) qua RPC Supabase.

6. BẢO MẬT & VALIDATION (SECURITY & VALIDATION)
-------------------------------------------------------------------------------
1. Chống Spam & DoS Server:
   - Client Queue Cap: Giới hạn tối đa 200 ván trong LocalStorage (`MAX_QUEUE = 200`). Sử dụng cơ chế FIFO đẩy ván cũ nhất ra ngoài khi đầy.
   - Server Batch Limit: Giới hạn tối đa 25 ván cho mỗi lượt request đồng bộ (`MAX_SYNC_BATCH = 25`). Nếu gửi > 25 ván, server lập tức từ chối với HTTP 413 (Payload Too Large).
   - Server Ticket Rate Limit: Tối đa 20 lượt khởi tạo ticket (`start-round`) trong vòng 1 phút cho mỗi người dùng (`MAX_TICKET_STARTS_PER_MINUTE = 20`).

2. Ràng buộc Thời gian & Tính Hợp lệ của Ván Offline:
   - Server kiểm tra `startedAt`: Từ chối ván nếu thời gian bắt đầu nằm ở tương lai (> 60s so với server clock) hoặc vượt quá 7 ngày tuổi (`MAX_OFFLINE_AGE_MS = 7 * 24 * 3600_000`).
   - Server kẹp giới hạn `clientElapsedMs`: Không tin tưởng tuyệt đối con số client gửi lên. Giá trị `elapsed` bắt buộc nằm trong khoảng `[500ms, 2 giờ]`:
     `const elapsed = Math.min(Math.max(Number(clientElapsedMs) || 0, 500), 2 * 3600_000);`

3. Idempotency & Chống Replay Attack:
   - Mỗi ván offline khi tạo ở client được gán một `clientRoundId` ngẫu nhiên chuẩn UUIDv4 (`crypto.randomUUID()`).
   - Server lưu `client_round_id` vào bảng `round_tickets`. Trước khi xử lý, server tra cứu `client_round_id` để phát hiện ván đã được nộp trước đó. Nếu đã chốt, trả về status `"duplicate"` mà không cộng điểm lần hai.

4. Anti-Cheat & Ghi nhận Dấu vết Gian lận:
   - Mặc dù ván offline không có `serverElapsedMs` chính xác từ ticket thời gian thực, server vẫn chạy toàn bộ bộ kiểm tra Anti-cheat `inspectRound(gameId, telemetry, elapsed)`.
   - Tự động chèn Soft Flag: `"Offline sync: timing verification bypassed"` để phân biệt ván đấu ngoại tuyến với ván đấu trực tuyến.
   - Nếu vi phạm Hard Flag (như gian lận phản xạ siêu nhiên, dữ liệu telemetry vô lý): Ticket bị hủy ngay lập tức và ván đấu bị từ chối (`status: "rejected"`).




7. TRẢ KẾT QUẢ ĐỒNG BỘ (SYNC RESULT UX)
- Khi `sync-offline-rounds` trả về `SyncResult` với các ván bị `rejected` (do anti-cheat hoặc quá 7 ngày), Client cần hiển thị Summary Notification cho người chơi. VD: "Đã đồng bộ 18 ván, 2 ván không hợp lệ bị từ chối". Các ván rejected sẽ bị loại bỏ khỏi queue im lặng nếu không có thông báo này.
- Cảnh báo dung lượng hàng đợi: Nếu `queue.length > 150`, hiển thị cảnh báo đỏ trên UI yêu cầu người dùng kết nối mạng (tránh chạm giới hạn 200 dẫn đến FIFO đẩy ván cũ ra ngoài).
- Ưu tiên đồng bộ: Các ván chơi sắp quá hạn 7 ngày cần được xếp lên đầu batch đồng bộ (ưu tiên gửi trước).
- Cảnh báo sắp quá hạn: Nếu có ván offline nằm trong queue quá 6 ngày (sắp quá hạn 7 ngày), hiển thị thông báo khẩn cấp trước 24h để người chơi kịp online đồng bộ.
